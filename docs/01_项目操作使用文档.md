# 项目操作使用文档

## 1. 项目简介

| 项目项 | 说明 |
| --- | --- |
| 项目名称 | Testin RecruitFlow Agent |
| 项目用途 | 面向招聘场景的 AI 候选人录入、跟踪、回溯和看板系统 |
| 面向用户 | HR、招聘团队、需要演示或验证 AI 招聘录入方案的开发者 |
| 核心功能 | AI 智能录入、文件解析、重复候选人检测、候选人管理、岗位管理、招聘进度表、原始输入回溯、Agent 日志、Dashboard、Kanban、用户登录与权限控制 |
| 项目组成 | Next.js 前后端一体应用、Prisma ORM、PostgreSQL 数据库、本地文件存储、可选大模型服务 |

系统核心闭环：

1. 用户在 `/intake` 上传简历或粘贴文本。
2. API 校验登录态和权限。
3. 系统解析文本或文件，并调用 mock、Qwen、DeepSeek 或 custom provider 生成候选人草稿。
4. 系统写入 RawInput 和 AgentTask，保留原文和 AI 处理日志。
5. 用户确认保存，系统创建或合并 Candidate，并同步 RecruitmentApplication、RecruitmentLog 和 Notification。
6. 用户在候选人列表、岗位进度表、Dashboard、Kanban、原始输入和 Agent 日志中查看结果。

## 6. 数据库初始化与数据准备

当前项目依赖 PostgreSQL，数据库结构由 Prisma migration 管理：

- 数据模型：`prisma/schema.prisma`
- 迁移目录：`prisma/migrations`
- 种子脚本：`prisma/seed.js`
- 演示数据源：`data/db.json`
- 用户种子数据源：`data/users.json`

首次初始化建议顺序：

1. 启动 PostgreSQL。
2. 生成 Prisma Client。
3. 执行迁移。
4. 导入演示数据。
5. 创建管理员和 HR 测试账号。

命令如下：

```bash
npm run prisma:generate
npx prisma migrate deploy
npm run db:seed
npm run admin:bootstrap -- --email admin@testin.local --name "Testin Admin" --password "Admin123456"
npm run hr:bootstrap
```

PowerShell 替代命令：

```powershell
.\node_modules\.bin\prisma.cmd generate
.\node_modules\.bin\prisma.cmd migrate deploy
npm run db:seed
npm run admin:bootstrap -- --email admin@testin.local --name "Testin Admin" --password "Admin123456"
npm run hr:bootstrap
```

验证方式：

1. 初始化命令无报错。
2. `npm run db:seed` 输出导入候选人、原始输入、Agent 任务、提醒和用户数量。
3. 启动项目后可以使用默认账号登录。
4. `/dashboard`、`/candidates` 能看到演示数据。

## 9. 核心功能使用说明

### 9.1 登录系统

**使用场景：** 进入系统页面和 API 前完成身份认证。

**前置条件：** 已初始化数据库并创建账号。

**操作步骤：**

1. 打开 `http://localhost:3000/login`。
2. 输入邮箱和密码。
3. 点击登录。

**预期结果：** 登录成功后写入 HttpOnly Cookie，并进入系统页面。

**常见问题：** 若提示“邮箱或密码错误”，确认账号初始化命令是否执行，或重新执行 `npm run admin:bootstrap`。

### 9.2 AI 智能录入

**使用场景：** 从简历、邮件、聊天记录或备注中生成候选人草稿。

**前置条件：**

- 已登录。
- 数据库中存在部门和岗位。
- 使用真实模型时已配置对应 API Key；本地演示可使用 `AI_PROVIDER=mock`。

**操作步骤：**

1. 打开 `/intake`。
2. 选择部门。
3. 选择部门下的目标岗位。
4. 选择 provider。
5. 粘贴文本或上传文件。
6. 点击解析。
7. 查看候选人草稿、缺失字段、标签、跟进建议和疑似重复提示。
8. 确认后保存候选人。

**输入说明：**

- 文本录入至少需要 10 个字符。
- 文件支持 PDF、DOCX、TXT、MD、JSON、CSV；单文件最大 8MB。

**预期结果：**

- RawInput 保存原始输入。
- AgentTask 保存 AI 子任务日志。
- 保存后生成或合并 Candidate，并同步岗位申请和提醒。

**常见问题：**

- 文件解析不到文字：可能是扫描件 PDF，当前未发现 OCR 能力。
- 真实模型失败：查看 `/agent-tasks` 中的错误信息。

### 9.3 候选人管理

**使用场景：** 搜索、筛选、查看、编辑或删除候选人。

**前置条件：** 已登录，系统中已有候选人数据。

**操作步骤：**

1. 打开 `/candidates`。
2. 使用关键词、状态、岗位、部门、来源、日期等条件筛选。
3. 点击候选人查看详情。
4. 根据需要编辑状态、备注、标签等字段。
5. 如需删除，可执行单条删除或批量删除。

**预期结果：**

- 列表展示候选人及岗位、状态、提醒等信息。
- 编辑状态时写入 RecruitmentLog 和 AgentTask。
- 删除候选人采用软删除，并软删除关联岗位申请。

### 9.4 岗位管理与招聘进度表

**使用场景：** 管理岗位、岗位 JD、自定义字段和岗位维度招聘进度。

**前置条件：** 管理岗位通常需要管理员权限；部分申请写入能力 recruiter 可执行。

**操作步骤：**

1. 打开 `/positions` 查看岗位列表。
2. 创建岗位时填写岗位名称、部门、HC、负责人、状态、优先级和 JD。
3. 打开 `/positions/[id]` 查看岗位招聘进度。
4. 打开 `/positions/[id]/settings` 配置岗位字段。
5. 在进度表中编辑候选人申请状态或自定义字段。

**预期结果：**

- 新岗位会自动初始化默认字段。
- 申请进度变更会写入 RecruitmentLog。
- 自定义字段变更会写入 ApplicationFieldChange。

**注意事项：** 系统字段不能删除；字段配置变更会使岗位申请 schemaVersion 递增。

### 9.5 原始输入回溯

**使用场景：** 排查 AI 抽取结果，查看原文和解析快照。

**前置条件：** 已完成至少一次 AI Intake。

**操作步骤：**

1. 打开 `/raw-inputs`。
2. 查看原文摘要、候选人关联和 AgentTask 数量。
3. 打开详情查看完整原文和解析结果。
4. 如有上传文件，可通过附件接口读取原始文件。

**预期结果：** 可以从原文追溯到候选人和 Agent 日志。

### 9.6 Agent 日志

**使用场景：** 排查 AI 任务、模型调用、重复检测和状态识别。

**操作步骤：**

1. 打开 `/agent-tasks`。
2. 查看任务列表。
3. 打开任务详情抽屉。
4. 查看 input、output、confidence、durationMs 和 error。

**预期结果：** 看到每次 AI Intake 拆分出的抽取、分类、标签、跟进建议、重复检测和状态任务。

### 9.7 Dashboard 与 Kanban

**使用场景：** 查看招聘总体指标和流程状态。

**操作步骤：**

1. 打开 `/dashboard` 查看图表、状态分布和待跟进。
2. 打开 `/kanban` 查看候选人按招聘阶段分布。
3. 如需导入 Dashboard 汇总数据，使用页面对应导入功能。

**注意事项：** Dashboard 汇总导入可能生成占位候选人，用于演示或汇总看板数据恢复。

## 11. 常见问题排查

| 问题现象 | 可能原因 | 排查步骤 | 解决方式 |
| --- | --- | --- | --- |
| `npm install` 失败 | Node 版本不符、网络问题、权限不足 | 检查 `node -v`、npm registry、目录权限 | 使用 Node.js 22.x，切换网络或 registry，确认目录可写 |
| `npx prisma ...` 被 PowerShell 拦截 | PowerShell 执行策略限制 `npx.ps1` | 查看错误是否包含 `无法加载文件 npx.ps1` | 使用 `.\node_modules\.bin\prisma.cmd ...` |
| 数据库无法连接 | PostgreSQL 未启动或 `DATABASE_URL` 错误 | 检查 `npm run db:local` 是否运行，检查 `.env` | 启动数据库并修正 `DATABASE_URL` |
| 5432 端口被占用 | 本机已有 PostgreSQL 或其他服务 | 查看端口占用情况 | 使用已有 PostgreSQL 或调整外部数据库配置；内置脚本默认使用 5432 |
| 3000 端口被占用 | 已有 Next.js 或其他服务运行 | 启动时报端口占用 | 关闭占用进程，或使用 Next.js 支持的方式指定其他端口 |
| 登录失败 | 账号未初始化、密码错误、数据库被重置 | 查询是否执行 bootstrap 脚本 | 重新执行 `npm run admin:bootstrap` 和 `npm run hr:bootstrap` |
| 登录后仍跳回登录页 | Cookie 未写入、`AUTH_SECRET` 变化、浏览器缓存问题 | 检查 `.env`，清理浏览器 Cookie | 固定 `AUTH_SECRET` 后重新登录 |
| API 返回 401 | 未登录或 Session 过期 | 查看响应 JSON | 重新登录 |
| API 返回 403 | 当前角色缺少权限 | 查看登录用户角色和接口所需权限 | 使用管理员账号或调整用户角色 |
| AI 调用失败 | API Key 缺失、Base URL 错误、网络不可达、额度限制 | 打开 `/agent-tasks` 查看 error | 先切换 `AI_PROVIDER=mock` 验证流程，再修正模型配置 |
| 文件解析无文本 | 扫描件 PDF、图片型简历、空文件或超过 8MB | 查看上传文件类型和大小 | 使用文本型 PDF/DOCX/TXT，或先 OCR 后上传 |
| 构建失败 | 类型错误、环境变量缺失、数据库生成客户端缺失 | 先执行类型检查和 Prisma generate | 运行 `npm run prisma:generate`、修复报错后再 build |
| 页面数据未刷新 | 读缓存仍在 TTL 内或写操作未触发对应失效 | 刷新页面或等待 10-30 秒 | 若持续存在，检查对应服务是否调用 `invalidateCacheByPrefix` |
| Docker 启动失败 | 当前项目未发现 Docker 配置 | 检查仓库文件 | 不使用 Docker 启动，按 Node.js 和 PostgreSQL 步骤启动 |
| Redis 无法连接 | 当前项目未使用 Redis | 检查依赖和配置 | 无需启动 Redis |
| 跨域问题 | 当前前后端同属 Next.js 应用，默认同源 | 确认是否通过同一站点访问 | 使用 `http://localhost:3000` 访问页面和 API |
